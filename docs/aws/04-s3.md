# Amazon S3 — Private Resume and Screenshot Storage

**Status: application S3 backend and Terraform bucket are implemented; live AWS access is unverified.** Resume objects use server-generated user-scoped keys, private bucket access, server-side encryption, and short-lived presigned download URLs. Local development uses private filesystem storage.

The backend ECS task role is granted object access. Keep Block Public Access enabled, bucket encryption and versioning enabled, and lifecycle rules reviewed. Inspect S3 → bucket → Permissions/Properties/Management in the Console. CLI read-only check: `aws s3api get-public-access-block --bucket <bucket>` and `aws s3api get-bucket-encryption --bucket <bucket>`. Terraform resources are in `infra/terraform/storage.tf`.

S3 charges depend on stored bytes, requests, retrieval, and transfer. Lifecycle rules can abort incomplete multipart uploads and expire old versions; review retention needs before applying. For access failures, verify the task role, bucket name, region, object key, and bucket policy. Deleting a resume bucket or versions can permanently destroy candidate documents; export backups and inspect the plan first.
